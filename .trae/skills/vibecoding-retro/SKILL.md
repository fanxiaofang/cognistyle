# Vibecoding 复盘分析

## 适用场景

- 用户说 "帮我复盘刚才的对话"
- 用户说 "分析我在这几轮对话里的提示词有什么问题"
- 用户说 "总结我的 vibecoding 优缺点"
- 用户说 "看看我的 token 消耗是否合理"
- 用户说 "对比我几段历史对话的表达问题"
- 完成一个功能模块后想做阶段性回顾

## 分析框架

对用户指定的对话（当前对话或指定的历史对话），按六个维度产出分析报告：

### 一、优点

从用户提问中提取 **3-5 个具体优点**，每条包含：
- 典型提问原话
- 为什么有效（对 agent 理解意图的帮助）

### 二、盲点与可改进之处

按**根因类型**分类（不是按对话时间线），每类包含：
- 盲点描述
- 典型原话
- 优化后的表达（对比展示）
- 该类型在跨项目中的通用性

常见盲点类型：
1. 量级模糊（"弱化一点"、"有点小"）
2. 范围缺失（"优化API"、"修改页面"）
3. 意图混淆（"xxx 什么意思"实际是想改）
4. 只有否定无方向（"不要这个"、"感觉不对"）
5. 缺少判断标准（"合理么"不提关注点）
6. 碎片化连续提问（一个新元素分4轮描述位置/样式/文案）
7. 修改前不做影响评估（同时改类型+数据+UI）
8. 同类问题反复出现不沉淀

### 三、Agent 使用效率

分为高效场景和低效场景：

| 场景 | 为什么高效/低效 | 改进方式 |

低效场景必须给出：不增加用户工作量的改进方式。

### 四、Token 消耗分析

- 列出高消耗场景及原因
- 指出哪些消耗是"必要投入"，哪些是"可避免的修复循环"
- 给一个总体的 token 节省空间估算（百分比或定性）

### 五、提示词质量评分

六维评分表（★ 1-5）：

| 维度 | 评分 | 说明 |
|------|:--:|------|
| 目标明确度 | | |
| 上下文充分度 | | |
| 约束描述 | | |
| 拆分粒度 | | |
| 给出样例 | | |
| 迭代指令质量 | | |

### 六、最具性价比的改进（3 条）

每条格式：
1. **改进方向**（一句话）
2. 反面示例（用户当前做法）
3. 正面示例（优化后的做法）
4. Token 节省预估

## 输出格式要求

- 整个报告使用中文
- 表格对齐，结构清晰
- 每个盲点至少配一组"原话 vs 优化版"对比
- 改进建议必须是**可操作的**（告诉用户具体怎么做，而非抽象原则）
- 如果用户只要求分析一部分维度，只输出对应部分

## 与 vibecoding-retro-agent 的分工

如果报告中需要提炼"跨项目通用原则"，应**在报告末尾**追加一节：

### 通用 Vibecoding 原则速查

只列 5-10 条，每条格式为：**原则名：** 一句话原则 + 一句话为什么。

这两节与主报告区分开——主报告 = 具体到本次对话，通用原则 = 可迁移到其他项目。如果用户未开启 `vibecoding-retro-agent`，则本 Skill 同时承担两项职责。
