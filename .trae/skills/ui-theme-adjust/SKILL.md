|------|------|---------|

| 中 | `border-2` | 普通卡片 |

### 字体层级

| 大小 | Tailwind | 使用场景 |
|------|----------|---------|
| 微小 | `text-[9px]` ~ `text-[11px]` | 徽章、辅助标签 |

| 大 | `text-base` ~ `text-lg` | 子标题 |
| 超大 | `text-2xl` ~ `text-5xl` | 主标题 |

### 响应式断点

| 前缀 | 宽度 |
|------|------|
| 无 | < 640px（移动端） |
| `sm:` | ≥ 640px |
| `md:` | ≥ 768px |
| `lg:` | ≥ 1024px |

## 批量调整流程

1. **定位**：用 Grep 在当前文件集合中搜索目标类名（如 `border-4`、`text-[8px]`）
2. **替换**：用 SearchReplace 批量替换，确保 `sm:` 响应式前缀保留
3. **验证**：运行 `npm run lint`，确认无语法问题

## 替换规则

- 边框减弱（`border-4` → `border-2`）：必须同步减少 `shadow-[0_0_Xpx]` 中的 X 值
- 字体放大（`text-[8px]` → `text-[11px]`）：不需要改 `sm:` 前缀的值
- 颜色透明度调整：只改 `/[0-9]+` 结尾的透明度值
- 移动端/桌面端区分：`sm:` 前缀的值保持不变，只改无前缀的基础值

## 跨平台兼容规则（强制）

项目目标平台：**Windows 桌面端** + **移动端浏览器**。每次 UI 修改必须遵循：

### 布局兼容

- **禁止依赖特定平台字体渲染高度**做对齐（如 `mt-5` 去凑 Press Start 2P 的行高），不同 OS 的字体度量不同
- 对齐方案优先用**结构调整**（同层 flex row + `items-start`）而非 magic margin
- 使用 `gap` 统一管理间距，避免分散的 `mt-*` / `mb-*` / `ml-*` / `mr-*`

### 字体兼容

- `font-pixel`（Press Start 2P）和 `font-display`（VT323）在 Windows 和移动端渲染高度不同，不要依赖其精确像素值
- 按钮/输入框的 `min-height` 和 `py` 必须同时设置，确保字体加载失败时仍有可用高度（当前规范：按钮 `min-h-[46px]` / `py-3`，小按钮 `min-h-[40px]` / `py-2`）

### 响应式兼容

- 桌面端（≥ `sm:`）：横向 flex row 布局为主
- 移动端（无前缀）：纵向 flex col 堆叠，按钮全宽 `w-full`
- 移动端输入框和按钮的触摸区域 ≥ 44px 高度（当前 `py-3` = 48px ✅）

### 验证清单

1. 改完后确认 `sm:` 前缀的布局改动同时适用于 ≥640px（桌面端）
2. 确认无前缀的基础布局在 <640px（移动端）正常堆叠
3. 检查是否有仅靠 margin 凑对齐的情况 → 改为结构调整
4. 运行 `npm run lint` 确认零类型错误

## 图标替换

可用图标库：`lucide-react`（已安装）

当用户要求换图标时：
1. 理解用户想要的感觉（工程感、终端感、循环感、切换感……）
2. 从 lucide-react 中选取语义最接近的图标
3. 更新 import 和 JSX 中的组件名
4. 运行 lint 验证
