
# 设计文档

## 概述

本文档描述 CogniStyle 认知风格测评系统中双人测试历史记录持久化存储的技术架构。该功能用基于 EdgeOne Pages Functions + KV 存储的混合架构取代原先仅依赖 localStorage 的方案，在服务端实现持久化，在客户端实现缓存，并保持灵活降级能力。

### 目标

1. **持久化存储**：历史记录存储于服务端，抵御浏览器缓存清理，支持跨设备访问
2. **性能保障**：通过客户端缓存和 stale-while-revalidate 策略保持快速响应
3. **优雅降级**：当服务器不可用时，自动回退为纯本地存储模式
4. **向后兼容**：将现有 localStorage 历史记录无缝迁移至新系统
5. **隐私与安全**：确保历史记录仅用户本人可访问，并通过速率限制加以保护

### 非目标

- 跨浏览器标签页的实时同步（最终一致性可接受）
- 全离线优先架构及复杂冲突解决（服务器版本优先）
- 历史记录版本回退或撤销/重做功能
- 用户之间共享历史记录

### 数据流

#### 读取流程（含缓存）

1. 用户打开历史页面 → `History_Service.getHistory(friendId)`
2. 检查 localStorage 缓存有效性（距上次获取 < 5 分钟）
3. 若有效：直接返回缓存数据
4. 若无效/缺失：从 History_API 获取 → 缓存结果 → 返回数据
5. 若 API 失败：返回已过期的缓存数据或空数组

#### 写入流程（双写）

1. 用户生成双人报告 → `History_Service.addHistory(entry)`
2. 乐观更新 localStorage 缓存
3. 异步 POST 至 History_API
4. 若 API 成功：用服务器时间戳更新缓存
5. 若 API 失败：保留仅本地条目，标记为待重试

#### 删除流程（双删）

1. 用户删除历史条目 → `History_Service.removeHistory(targetFriendId)`
2. 乐观从 localStorage 缓存中移除
3. 异步 DELETE 至 History_API
4. 若 API 失败：恢复本地条目，显示警告

#### 自动同步流程

- 页面加载时，消费待同步操作队列
- 监听浏览器 `online` 事件，当网络由断线转为连接时，立即尝试消费待同步队列
- 每隔 60 秒通过 `HEAD /api/dual-history/health` 检测服务可用性；若服务从不可用恢复为可用，触发队列消费

### 组件职责

| 组件 | 职责 |
|------|------|
| **History_Service** | API 客户端、缓存管理、降级逻辑、迁移流程 |
| **History_API** | 请求校验、速率限制、KV 操作、错误处理 |
| **KV_Store** | 带 TTL 的持久化存储、原子操作 |
| **localStorage** | 快速缓存、离线后备、迁移数据源 |

**实现策略**：
- 使用 stale-while-revalidate：立即返回缓存，后台拉取服务器数据，以服务器时间戳更新缓存
- 写入操作使用 500ms 防抖
- 失败操作放入同步队列，在下次页面加载或网络恢复时重试
- 同步队列存储于 `localStorage` 键 `cognistyle_history_sync_queue`，条目包含操作类型、参数及时间戳，超过 7 天未成功同步的条目自动清除
- 缓存元数据与历史条目分开存储

### 后端：History_API

**文件**：`functions/api/dual-history.js`

**端点说明**：

#### POST /api/dual-history
添加或更新一条历史记录。

**请求**：
```typescript
{
  friendId: string;          // 所有者 friendId
  version: 'history-v1';
  entry: {
    targetFriendId: string;
    targetProfileId: ProfileId;
    targetDisplayName: string;
    targetCallSign: string;
    targetDepartment: string;
    overallScore: number;
    pattern: CompatibilityPairPattern;
    generatedAt: number;
  }
}
```

**成功响应**（200 OK）：
```typescript
{
  data: {
    success: true;
    syncedAt: number;
    totalEntries: number;
  }
}
```

**错误响应**（统一格式）：
```typescript
{
  error: {
    code: string;      // 例如 "BAD_REQUEST"、"RATE_LIMITED"、"NOT_FOUND"
    message: string;   // 面向用户的描述
  }
}
```

**错误码**：
- `400 BAD_REQUEST`：friendId 格式无效、必填字段缺失、版本无效
- `404 NOT_FOUND`：friendId 不存在或已过期
- `409 CONFLICT`：版本不匹配
- `429 RATE_LIMITED`：请求过于频繁
- `500 INTERNAL_ERROR`：KV 操作失败

#### GET /api/dual-history/:friendId
获取指定用户的所有历史记录。

**请求**：URL 参数 `friendId`

**成功响应**（200 OK）：
```typescript
{
  data: {
    friendId: string;
    version: 'history-v1';
    entries: DualReportHistoryEntry[];
    fetchedAt: number;
  }
}
```

**行为**：
- 当 `friendId` 不存在或已过期时，返回 `200 OK` 及空数组 `{ data: { entries: [] } }`（对新用户友好）
- 当 `friendId` 存在时，返回全部历史记录

**错误**：
- `400 BAD_REQUEST`：friendId 格式无效
- `429 RATE_LIMITED`
- `500 INTERNAL_ERROR`

#### DELETE /api/dual-history
删除单条或全部历史记录。

**请求**：
```typescript
{
  friendId: string;           // 所有者 friendId
  targetFriendId?: string;    // 若省略，则删除全部
}
```

**成功响应**（200 OK）：
```typescript
{
  data: {
    success: true;
    deleted: number;          // 实际删除条目数
  }
}
```

**错误**：
- `400 BAD_REQUEST`
- `404 NOT_FOUND`
- `429 RATE_LIMITED`
- `500 INTERNAL_ERROR`

#### POST /api/dual-history/batch
批量写入历史记录，用于数据迁移或大批量操作。

**请求**：
```typescript
{
  friendId: string;
  version: 'history-v1';
  entries: Array<{
    targetFriendId: string;
    targetProfileId: ProfileId;
    targetDisplayName: string;
    targetCallSign: string;
    targetDepartment: string;
    overallScore: number;
    pattern: CompatibilityPairPattern;
    generatedAt: number;
  }>;
}
```

**成功响应**（200 OK）：
```typescript
{
  data: {
    success: true;
    syncedAt: number;
    totalEntries: number;
  }
}
```

**行为**：
- 批量处理等同于若干次单个写入，但整体计为 1 次写入操作（受写入速率限制控制）
- 若列表中存在与已有 targetFriendId 重复的条目，则更新覆盖；其余新增
- 最终总条目数仍限制 50 条，超出部分按时间顺序保留最新

**错误**：与 POST 单条相同。

#### HEAD /api/dual-history/health
健康检查端点，用于离线探测。

**请求**：HEAD 请求，无请求体

**成功响应**：`204 No Content`

**行为**：
- 不纳入速率限制计数
- 应在 3 秒内响应
- 可用于前端周期性检测服务可用性

**错误**：
- `500 INTERNAL_ERROR`：服务不可用

**实现注意事项**：
- 复用 `api-utils.js` 中现有工具方法：`getSnapshotKv`、`hitRateLimit`、`extractClientIp`、`validateFriendIdFormat`、`json`
- 复用 `api-constants.js` 中的 `COMMON_HEADERS`、`TTL`、`DEFAULT_RATE_LIMIT`
- 新增常量：`KV_KEY_PREFIXES.HISTORY = 'history:'`、`DEFAULT_RATE_LIMIT.HISTORY_READ_MAX = 30`、`DEFAULT_RATE_LIMIT.HISTORY_WRITE_MAX = 10`、`DEFAULT_RATE_LIMIT.HISTORY_DELETE_MAX = 5`
- HEAD /health 不计入速率限制
- GET 对不存在的 friendId 返回 200 及空数组；POST/DELETE 返回 404（要求有效的认证）

## 数据模型

### KV 存储模型

**键格式**：`history:{friendId}`

**值（JSON）**：
```typescript
{
  version: 'history-v1';       // 协议版本
  friendId: string;
  entries: Array<{
    targetFriendId: string;
    targetProfileId: ProfileId;
    targetDisplayName: string;
    targetCallSign: string;
    targetDepartment: string;
    overallScore: number;
    pattern: CompatibilityPairPattern;
    generatedAt: number;
  }>;
  updatedAt: number;           // 最后修改时间戳
}
```

**TTL**：90 天（与快照 TTL 一致，使用 `TTL.SNAPSHOT_SECONDS`）

**容量约束**：
- 每个 friendId 最多 50 条条目
- 每条约 200 字节，总计约 10 KB，远低于 KV 限制

### localStorage 模型

**键**：`cognistyle_dual_history_v2`（从 `v1` 更名以触发迁移）

**值（JSON）**：
```typescript
{
  version: 'history-v1';
  friendId: string;           // 新增：关联特定用户
  entries: DualReportHistoryEntry[];
  fetchedAt: number;          // 新增：缓存时间
  migrated?: boolean;         // 新增：迁移标志
}
```

**迁移策略**：
1. 首次加载新版本时，检查旧键 `cognistyle_dual_history_v1`
2. 若存在且用户有有效 friendId，调用 `migrateLocalHistoryToServer()`
3. 使用批量接口 `POST /api/dual-history/batch` 或分批上传（每批最多 8 条，间隔 60 秒），避免触发速率限制；迁移过程中展示进度
4. 迁移成功后，在新键中标记 `migrated: true`，删除旧键
5. 若迁移失败，保留旧数据，下次页面加载时重试

## 错误处理

### 错误分类

| 类别 | HTTP 状态码 | 错误代码 | 用户消息 | 降级行为 |
|------|------------|----------|----------|----------|
| 网络错误 | - | NETWORK_ERROR | “网络连接失败，使用本地缓存” | 使用过期缓存或空数组 |
| 速率限制 | 429 | RATE_LIMITED | “请求过于频繁，请稍后重试” | 使用过期缓存，阻止新写入 |
| 未找到 (POST/DELETE) | 404 | NOT_FOUND | “记录不存在或已过期” | 显示错误信息 |
| 未找到 (GET) | 200 | - | - | 返回空数组（对新用户友好） |
| 请求错误 | 400 | BAD_REQUEST | “请求格式错误” | 记录日志，使用缓存 |
| 版本冲突 | 409 | CONFLICT | “数据版本不匹配，请刷新页面” | 强制从服务器刷新 |
| 服务器错误 | 500 | INTERNAL_ERROR | “服务器错误，已保存到本地” | 仅保存至 localStorage |

### 优雅降级策略

**离线模式检测**：
```typescript
let isOfflineMode = false;
let lastServerCheckAt = 0;

async function checkServerAvailability(): Promise<boolean> {
  if (Date.now() - lastServerCheckAt < 60000) {
    return !isOfflineMode;
  }

  try {
    const response = await fetch('/api/dual-history/health', {
      method: 'HEAD',
      signal: AbortSignal.timeout(3000)
    });
    isOfflineMode = !response.ok;
  } catch {
    isOfflineMode = true;
  }

  lastServerCheckAt = Date.now();
  return !isOfflineMode;
}

// 网络恢复时自动同步
window.addEventListener('online', () => {
  if (!isOfflineMode) processSyncQueue();
});

// 周期性健康检查，从离线恢复后触发同步
setInterval(async () => {
  const wasOffline = isOfflineMode;
  const available = await checkServerAvailability();
  if (wasOffline && available) {
    processSyncQueue();
  }
}, 60000);
```

**降级行为**：
- 读操作：返回缓存数据并显示“离线模式”提示
- 写操作：存入 localStorage 并标记 `localOnly: true`
- 删除操作：本地标记删除，重连后同步
- 界面提示：在历史页面头部显示“离线模式”徽章

### 重试逻辑

**指数退避**：
```typescript
async function retryWithBackoff<T>(
  fn: () => Promise<T>,
  maxRetries = 3
): Promise<T> {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn();
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, Math.pow(2, i) * 1000));
    }
  }
  throw new Error('Max retries exceeded');
}
```

**同步队列**：
- 存储键：`cognistyle_history_sync_queue`
- 每个操作包含：`{ type: 'add'|'delete', payload: any, timestamp: number }`
- 限制队列长度为 20 条，FIFO；超过 7 天未成功的条目自动移除

## 安全措施

### 认证与授权

- 简化认证：以 `friendId` 作为隐式令牌（无独立认证系统）
- 所有权验证：API 通过检查 KV 中 friendId 是否存在来确认身份
- 无跨用户访问：历史记录严格按 friendId 隔离
- 注意：此方案适用于低敏感度数据；friendId 效果等同于持有令牌

### 速率限制

**每个 IP 在 60 秒窗口内的限制**：
- 历史读取（GET）：30 次
- 历史写入（POST / POST batch）：10 次
- 历史删除（DELETE）：5 次
- 健康检查（HEAD）：不计入限制

**实现示例**：
```javascript
const RATE_LIMITS = {
  READ: { prefix: 'rate-limit:history-read:', max: 30 },
  WRITE: { prefix: 'rate-limit:history-write:', max: 10 },
  DELETE: { prefix: 'rate-limit:history-delete:', max: 5 },
};
```

### 数据隐私

**存储内容**：
- 目标用户的公开资料（displayName、callSign、department）
- 兼容性分数与模式
- 时间戳

**不存储内容**：
- 原始测试答案
- deleteToken
- IP 地址（仅用于速率限制，不持久化）
- 邮箱或任何个人标识

**数据保留**：
- 历史条目：90 天
- 速率限制计数器：60 秒
- 同步队列：成功同步后清除，超过 7 天未同步的条目自动清除

### 输入校验

**friendId 校验**：
```javascript
function validateFriendId(id) {
  return (
    typeof id === 'string' &&
    id.length >= 6 &&
    id.length <= 32 &&
    /^[a-zA-Z0-9_-]+$/.test(id)
  );
}
```

**条目校验**：
```javascript
function validateHistoryEntry(entry) {
  const errors = [];
  if (!validateFriendId(entry.targetFriendId)) errors.push('Invalid targetFriendId');
  if (typeof entry.overallScore !== 'number' || entry.overallScore < 0 || entry.overallScore > 100) errors.push('overallScore 范围 0-100');
  const validPatterns = ['homogeneous', 'complementary', 'asymmetric', 'conflicting'];
  if (!validPatterns.includes(entry.pattern)) errors.push('无效 pattern');
  if (typeof entry.generatedAt !== 'number' || entry.generatedAt <= 0) errors.push('无效 generatedAt');
  return errors.length > 0 ? errors : null;
}
```

## 测试策略

### 属性测试适用性

**评估**：属性测试（PBT）**不适用**于本功能。

**理由**：
- 核心为基础设施集成（EdgeOne Pages Functions + KV）及副作用协调
- 行为以 CRUD、降级、缓存为主，非纯数据变换
- 更适合基于模拟的单元测试、集成测试及基于示例的测试

### 单元测试（前端，模拟 fetch）

1. 缓存命中：有效期内直接返回，无 API 调用
2. 缓存缺失：从 API 拉取并缓存
3. 缓存过期：重新拉取，更新缓存
4. API 失败但有过期缓存：返回过期缓存
5. API 失败且无缓存：返回空数组及错误
6. 写入成功：更新 localStorage，调用 API，更新 syncedAt
7. 写入失败：更新 localStorage，标记 localOnly
8. 删除成功：移除缓存，调用 API
9. 删除失败：恢复本地条目并警告
10. 迁移检测：发现 v1 数据，调用批量上传，标记完成
11. 防抖：多次快速写入，仅最后一次触发 API 调用
12. 重试：指数退避重试
13. 同步队列：失败操作入队，网络恢复后重试

### 后端单元测试（模拟 KV）

1. POST 校验：无效 friendId 格式、缺失字段、无效分数、无效 pattern
2. POST 创建新条目
3. POST 更新已有条目（覆盖所有字段）
4. POST 触发 50 条上限，删除最旧
5. POST 对不存在/过期 friendId 返回 404
6. GET 成功返回全部条目
7. GET 不存在/过期 friendId 返回 200 + 空数组
8. DELETE 单条及全部
9. DELETE 不存在 friendId 返回 404
10. HEAD 健康检查返回 204，不计入速率限制
11. 速率限制（读、写、删）触发 429
12. 版本不匹配返回 409
13. 批量写入：批量创建、去重更新、总量限制

### 集成测试

1. 正常流程：生成报告 → 存储至 KV → 另一“设备”读取
2. 更新流程：同一 target 两次报告 → 仅保留最新
3. 删除流程：添加后删除 → KV 中清除
4. 清空流程：添加多条 → 清空 → KV 键移除
5. 迁移流程：填充旧 localStorage → 触发迁移 → 所有条目出现在 KV，旧键删除
6. 离线至在线：离线写入 → 服务恢复 → 自动同步队列
7. 缓存刷新：服务器更新 → 客户端获取 → 缓存更新
8. 并发写入：两个标签页写入不同条目，无冲突
9. 50 条目限制：添加 51 条，验证最旧被移除
10. TTL 过期：创建后快进 91 天，条目消失
11. 新用户 GET：返回 200 + 空数组

### 边界与异常场景

1. 空历史 GET → 返回 200 空数组
2. 重复 targetFriendId POST → 更新而非重复
3. 过期 friendId POST → 404
4. 过期 friendId GET → 200 空数组
5. localStorage 数据损坏 → 忽略缓存，从服务器重新获取
6. 50 条历史 → 全部返回，客户端无需分页
7. 网络超时 → 使用过期缓存
8. 迁移部分失败 → 重试失败条目
9. API 返回格式错误 → 降级到缓存并记录日志
10. CORS 阻止 → 视作网络错误
11. KV 不可用 → 返回 500，客户端回退本地
12. 健康检查超时 → 标记为离线
13. 健康检查不计速率限制 → 连续 100 次请求无 429

### 性能基准

- API 读取：< 200ms（P95）
- API 写入：< 300ms（P95）
- 50 条迁移时间：< 5 秒
- localStorage 读写：< 5ms（P95）

### 4. 注意事项

- **内存 KV 重启即清零**：每次 `npm run dev:api` 重启后，所有数据丢失，需要重新保存 result 快照
- **history API 要求 friendId 存在**：POST/DELETE 检查 `result:{friendId}` 是否在 KV 中存在，不存在返回 404。需要先通过 `/api/results` 创建用户
- **速率限制**：60s 窗口内读 30 次 / 写 10 次 / 删 5 次，触发后返回 429
